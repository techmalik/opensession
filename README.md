# OpenSession

OpenSession is an open-source replacement for Sessionboard, the speaker and content
management system conferences use to run a call for papers, review abstracts, build
an agenda, and manage speakers. It was built solo over a weekend for swyx's Kill My
SaaS competition. Live at https://opensession.opensession.workers.dev.

It includes built-in blind peer review, which the lighter CFP tools lack, without the
enterprise per-module pricing.

## What it covers

An organizer runs a program end to end in one app: a public call for papers with
custom fields that show and hide conditionally, blind multi-round review with
evaluation plans and reviewer recusal, accept and decline queues where the decision
emails are a deliberate separate send step and carry .ics attachments, an agenda that
detects room and speaker double-booking server-side with an AI assist that falls back
to a deterministic greedy packer when no model is available, a speaker portal with
tasks and versioned file requests, five public embed widgets plus JSON and iCal
feeds, an organization-level speaker CRM that spans events, a public REST API with
token auth, two-way Airtable sync, Brevo email with a full in-app send log, and
automated task reminders on a cron. Rejected speakers can be sent specific feedback
with their decline email, written per submission from the decline queue.

a CSV export.

## Architecture

One Cloudflare Worker serves the admin app, the public pages, the widgets, the API,
and the cron handler. React Router v7 in framework mode renders on the server; the
client bundle carries only what interaction needs.

- **Runtime**: React Router v7 SSR on Cloudflare Workers. Entry `workers/app.ts`.
- **Data**: D1 (SQLite) via Drizzle ORM, 45 tables, migrations generated by
  drizzle-kit and applied by wrangler.
- **Background work**: a `jobs` outbox table in D1, drained by a 5 minute cron.
  Cloudflare Queues need a paid plan, so this deliberately avoids them. Email
  retries, reminders, digests, and integration sync all go through it.
- **Files**: blobs in D1 by default, with R2 available behind the same
  `app/lib/storage.ts` interface.
- **Auth**: PBKDF2-SHA256 over WebCrypto, 100k iterations, signed session cookie.
  Roles: admin, organizer, evaluator, speaker.
- **AI**: Workers AI binding first, then `ANTHROPIC_API_KEY`, then a deterministic
  heuristic. Output is validated against real rooms, days, and slots.
- **Widgets**: server-rendered HTML with zero client JavaScript, served with
  `Content-Security-Policy: frame-ancestors *`, so they embed on any site.

## MCP

An MCP server at `/mcp` lets an AI agent run the conference program directly: it
speaks the streamable HTTP transport over JSON-RPC 2.0 and wraps the same `/api/v1`
layer, authenticated with the same API token as an `x-access-token` or
`Authorization: Bearer` header. Eleven tools cover events, session search and
editing, speakers, the submission queues, accept and decline, the agenda, and
outstanding speaker tasks; a token reaches only the events the organizer who created
it can open. Copy-paste config for Claude Code and Codex is on
[/docs/api](https://opensession.opensession.workers.dev/docs/api).

## Self-hosting

A Cloudflare free plan is enough: no Queues, no Durable Objects, no paid bindings.

```bash
npx wrangler login
npx wrangler d1 create opensession-db     # paste database_id into wrangler.jsonc
npx wrangler secret put SESSION_SECRET
npm run db:remote
npm run deploy
```

Optional secrets, each of which degrades cleanly when absent:

| Secret | Without it |
|---|---|
| `BREVO_API_KEY` | Email is recorded with status "test" and never delivered. Every screen still works. |
| `AIRTABLE_API_KEY`, `AIRTABLE_BASE_ID` | Airtable sync is off. |
| `ANTHROPIC_API_KEY` | AI features fall back to Workers AI, then to a deterministic heuristic labelled as such. |

Deploy with `npm run deploy`, never bare `wrangler deploy`: the bare command ships
the previous build's `build/server/wrangler.json`, stale vars included.

For local development:

```bash
npm install
cp .dev.vars.example .dev.vars   # set SESSION_SECRET at minimum
npm run db:local                 # apply migrations and seed to local D1
npm run dev
```

## Honest limitations

- Agenda conflicts are warned, not blocked. Double-booking a room or a person is
  detected server-side on every render and surfaced, but the organizer can still save
  it, because real programs sometimes need a deliberate overlap.
- Contact merge is not reversible. It re-points event history, sessions, notes, and
  mail onto the primary contact, drops rows that would collide with unique indexes,
  and deletes the loser.
- No XML feed. JSON and iCal only.
- D1 is single-region. Reads are fast at the edge, writes go to the primary region.
- File storage in D1 suits small files. Use R2 beyond that; it sits behind the same
  storage interface.
- No payments of any kind.
- English only. No localization layer.
- No dark mode. DESIGN.md puts it out of scope, and half-shipping it looked worse than
  not shipping it.
- The Accelevents integration is best effort, written against their public docs.
- No test suite. Verification is `npm run typecheck && npm run build` plus clicking
  the flow, which is what the deadline allowed. The eval kit in `spec/` is the closest
  thing to an integration test.
- No rate limiting on signup, login, public submission, or `/mcp`. It is deliberately
  deferred until after the evaluation window, because IP-based limits would throttle
  the automated judge; the planned mitigation is Cloudflare's Workers Rate Limiting
  binding.

## Repository map

```
workers/app.ts          Worker entry: fetch handler plus the scheduled() cron
app/routes.ts           the full route table
app/routes/*.tsx        one module per screen
app/lib/*.server.ts     queries and side effects, never imported by a component
app/lib/*.ts            client-safe constants and view types
app/components/         shared UI primitives (ui.tsx) and widget chrome (embed.tsx)
database/schema.ts      45 tables, Drizzle
database/seed.sql       generated by `npm run seed:gen`
drizzle/                12 migrations, generated except the two data backfills
spec/                   the vendored eval kit: rubric, scenarios, fixture data
prompts/                the phase-by-phase build prompts
```

`CLAUDE.md` holds the build rules and accumulated environment notes. `DESIGN.md` is
the enforced design system.
